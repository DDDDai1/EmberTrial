## 1. 本章结束时的可玩流程

```text
主菜单 → 开始试炼 → 现有战斗房间
                     ↓ 玩家真实死亡
                   失败界面 → 从检查点重试 → 新世界 / 新身体 / 新HUD
                     ↑
              抵达并激活会话检查点

战斗中P → 暂停菜单 → 继续 / 返回主菜单
主菜单 → 继续本次试炼 → 最近会话检查点
主菜单 → 退出游戏
```

本章检查点是**当前进程中的会话快照**，先保存地图标识与稳定检查点ID。死亡重试 / 菜单继续按最近检查点重新载入房间，玩家满血，敌人 / 训练目标 / 练习交互回到地图初始状态。使用新对象恢复，不移除Dead Tag给旧尸体“复活”。新游戏清空本次检查点并从入口开始。

**退出程序后会话检查点清除。**C已接入“继续本次试炼”和会话说明；新会话禁用，已有会话时启用。版本化存档、损坏回退、跨启动继续、已完成遭遇 / 奖励恢复仍由M5扩展。本章用一个入口和一个检查点证明生命周期闭环，不保存任意Actor地址或运行时ASC实例。

## 3. 对象归属与低耦合边界

当前主菜单Controller将相同请求前置条件与UIOnly / 初始焦点设置各集中一处；开始 / 继续的World前提和退出的原范围保持。Controller与Widget的pending / busy分别守住命令层和呈现层，不能只因都是布尔状态就删除其中之一。地图默认值和层级属于既有装配选择，仍可配置地图Class / 软引用，不新建通用菜单框架。

| 对象 | 归属 / 职责 |
| --- | --- |
| Menu GameMode（核心） | 当前菜单世界的规则：不生成玩家Pawn / Spectator / HUD；Controller Class由菜单GameMode BP装配，不反向引用UI模块 |
| MainMenu Controller（UI模块） | 本地菜单世界的View创建、三按钮命令、UI Only / 焦点和结束清理；统一调用会话服务，C继续已验收 |
| MainMenu Widget | 展示按钮 / 状态，发送开始 / 继续 / 退出意图；Blueprint负责布局，C++负责按钮事件；不Cast角色、无ASC、不负责存档规则 |
| Run Session（B / C已实现，GameInstanceSubsystem） | 跨地图保留地图包名、稳定ID、待定请求与已确认快照；不长期持有旧World、Controller、Pawn、Widget或ASC；不依赖UMG |
| 游戏GameMode（C已验收） | 生成身体前按稳定ID选择PlayerStart、校验唯一入口与缺失ID回退；出生完成通知实际选择，避免把无效ID继续保存；不处理UMG输入 |
| CheckpointStart（C已验收） | 继承PlayerStart，原生Sphere接收合法本地存活身体的Overlap；一次NextTick补出生重叠，事件更新占位反馈，EndPlay解绑；无逐帧检测 |
| Controller所属UI协调（B失败 / [D](M1_06D_PauseFlow.md)暂停均已验收） | 同一FailureFlow持有互斥Pause / Failure，当前Life死亡优先、会话命令、输入 / 暂停与解绑；保留既有类名 / BP配置，Core Controller只广播意图，提示由BP事件桥接 |
| LocalPlayer Subsystem / Presenter / HUD（现有） | LocalPlayer切图后绑定新Controller / Pawn；旧事件主动解绑，新健康快照推动既有HUD；沿用既有真实实现 |
| Actor / GAS / AI（现有） | 新地图实例重新初始化独立属性 / 能力；旧AI任务 / 委托 / Trace结束；不由菜单直接修复它们的状态 |

M1-06先采用**非无缝OpenLevel整图重建**，适合目前的小房间与离线玩法：世界Actor状态从地图配置重置，GameInstance / LocalPlayer保留。以后大关卡的原地重生 / 遭遇恢复需明确重置范围再扩展，不能把这条原型路线直接套到复杂开放世界。

菜单地图独立于战斗地图，避免开局敌人已经运行、角色已经死亡或HUD穿在菜单背景上。软地图引用不主动同步加载整个战斗场景；两张地图仍必须显式列入Cook配置。核心始终不依赖UI。

## 4. 本章检查重点

| 新边界 | 最小相关检查 |
| --- | --- |
| A菜单世界 | 无玩家身体 / 战斗HUD；鼠标和Tab / Enter / Space；连续点击只发一个切图请求 |
| A菜单→战斗 | 旧菜单移除、新Controller / Pawn / 单HUD、鼠标隐藏、无需额外点击即可移动 / 转向；菜单按键不补动作 |
| B真实死亡→失败 | 只显示一份失败页、死亡能力 / Trace / AI已停；按钮可操作，不让P再叠开旧菜单 |
| B重试 | 所有旧世界事件结束，新身体 / 敌人满血，新的HUD只观察新源；两轮正常重试，不重做独立属性完整矩阵 |
| C检查点 | 激活实际ID后重试出生到对应点；开始新游戏清空，菜单继续恢复本次ID；非法ID有明确回退 |
| D暂停 / 返回菜单 | 键鼠继续、背景焦点、无卡键 / 补播；暂停→菜单→继续的旧页 / 旧世界清理 |

不用再写五个Controller临时测试函数或反复搭换身体入口。正式按钮和流程本身就是可复用验证入口。难抓的时序优先通过完整日志与已有规则确认，亚秒操作不要求你反复盲试。
