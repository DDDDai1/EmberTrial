## 1. 要交付的体验

键鼠玩家按Tab选择镜头前方合法敌人，可清楚识别当前目标；锁定镜头与战斗朝向按明确规则响应，能够解除、切换，目标死亡 / 销毁 / 遮挡或越界、玩家换身体和切图时正常清理。既有攻击 / 闪避 / 治疗 / F保持各自状态与结算权，锁定不能让原本不合法的命中变成合法。

第一版只支持同World的Ready存活Enemy；Neutral训练身体不成为锁定对象。先形成一个目标身份，再做UI和镜头，避免多个系统各自选择不同目标。无联机预测、手柄交付、自动命中、武器追踪或新敌人美术。

## 3. 职责、生命周期与性能

- **Core锁定组件**拥有当前目标与选取 / 脱锁规则，Controller跨Possess存在，但新身体不自动继承旧锁；弱引用不阻止目标销毁。候选只在用户请求时Overlap，维持只检查当前目标。
- **UI / 标记**订阅同一个目标变化源、读投影与状态，不自行另选目标、写GAS或改变伤害。
- **镜头层**只在锁定活动期间更新，明确跟随 / 自由输入 / 解锁归还规则；动作中不能每帧强改Actor旋转，覆盖已有Montage的方向锁定。A先不改角色移动和能力。
- **Gameplay**继续由能力预检、Trace、GE / CombatLife / CombatPoise处理承伤、受击 / 破势与死亡。暂时无敌或Stunned不等同目标消失。
- **释放协议**先撤销身份 / 代次与Timer，再解绑当前来源，最后广播；EndPlay / 失活先封闭请求，旧回调不能重建新锁。暂停按游戏时间冻结，不补算整段现实时间。

A默认1200cm获取 / 1500cm脱锁、视锥半角60°、视角权重.75、维持.10秒、遮挡宽限.35秒，集中为组件配置；实际观察后再调，不在多处重复同值。Visibility沿用当前碰撞契约，不另建穿墙锁定路径。没有新性能测量时只描述更新策略，不宣称帧率提高。
