## 3. 核心设计约束

1. **资源与Ready。**不重命名现有HealthAttributes默认子对象来拆类，避免破坏已有Blueprint序列化；战斗属性单独成集，先定义初始化 /上限 /合法0 /重复Possess语义。正式Ready必须能说明资源可用，不能HUD显示Ready而成本属性未就绪。治次数是有限离散资源，有明确接口 /生效事务，不将每个整数都塞进AttributeSet。
2. **唯一动作所有者。**正式动作由GAS Tag /Ability控制，位移服务只拥有RootMotionSource /运动时段；Montage结束和位移结束职责分离。复用M0已验证的方向固定 /墙坡扫碰 /世界时间思路，迁移期间不让Practice和GA同时响应同一正式输入。具体抽取服务 /helper方式在对应源码指南确认，不为路线先建冗余组件。
3. **取消是协议。**当前Montage实例、Trace Serial、移动Source ID、Delegate Handle、计时器与缓冲各有所有者。完成 /取消 /死亡 /EndPlay走共同释放路径；只取消自己的资源，不把其他新动作的回调当旧动作结束。
4. **成本有时点。**闪避正常提交后消费；治疗在成功生效点消费次数；破势冷却 /效果只有一个提交点。处理同帧取消 /重复Notify /失败配置，拒绝时不留忙碌Tag或吞资源。不能先做表现再补交易语义。
5. **数据驱动与资产契约。**能力子蓝图配GE /Montage /数值，代码处理规则 /状态 /窗口有效性。M1校验器Profile按新资产 /属性有意识扩展，不能对新的正确Montage Slot /技能形态套旧契约误报。
6. **UI仍事件驱动。**体力 /次数 /冷却按事件 /快照驱动最低反馈；可见冷却时间展示可以有限刷新，不能为UI便利每帧扫描全ASC。M3再做完整页面 /构筑，不在M2展开大型UI框架。
7. **锁定算法。**候选容器与身份明确，按距离 /视角 /可见性线性选优或小规模排序；按需 /限频查找。目标死亡 /销毁 /越界 /遮挡超时 /Pawn更换撤销。不要每帧GetAllActorsOfClass扫描关卡。
