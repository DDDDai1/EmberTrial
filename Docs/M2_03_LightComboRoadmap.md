## 2. 数据与职责

- **既有LightAttack能力**继续共用真实伤害提交函数与无敌门控；玩家通过显式三段配置启用连段，敌人默认仍单段。先用小型段配置数组装配Montage / 伤害倍率 / 时段，暂不增加独立DataAsset与第二个伤害系统。
- **Ability**拥有整条链、段索引 / 代次、Montage Task和待消费输入。一次点击若在活动玩家连段中，进入实例的明确请求接口，不对活动能力重复TryActivate；敌人忙碌请求不进入玩家缓冲。
- **输入缓冲**最多1条，暂定有效0.25世界秒；新单次输入可以更新这1条的时间，不能累积两条。允许推进时读取过期状态，每次推进最多消费一次，推进后清空；第3段不排第4段。最终值由B实机校准。
- **推进时段**计划由原生Montage NotifyState驱动，并带当前Montage实例 / 窗口Token / 段代次身份。第1 / 2段暂定18–24帧（.60–.80秒）；过早输入若到窗口时已过期便丢弃，有效输入在窗口打开或窗口内新输入时推进。A只加已有命中通知，等B原生类编译后再加连段通知。
- **Trace**每个新段先关闭前段、再分配独立Serial和SeenTargets；同目标每段最多一次，三段最多3次。旧Notify结束 / 旧Task回调不得关闭新段窗口，不能只把整个Combo当一个Serial。遮挡与无敌拒绝仍消费当前段候选，下一段重新判定。
- **取消**先使旧段回调失效、关闭当前Trace / 清输入，再停止自己的Montage。受击 / 死亡从任意段取消；恢复闪避窗口只在命中结束后开放，C需先做闪避合法性 / 成本预检，避免非法闪避先把攻击取消。
- **暂停**冻结世界时钟与动作；暂停前已接受且尚有效的缓冲随世界时间冻结，暂停菜单期间输入不入队，恢复也不把菜单按键生成新输入。原Flush / 焦点规则沿用。

B / C实现时会重核具体回调重入和Timer语义，不靠按动画长度Delay解锁，也不让UI / AnimBP负责伤害或段推进。没有新全局事件总线、常驻Tick组件或逐帧扫描世界。
