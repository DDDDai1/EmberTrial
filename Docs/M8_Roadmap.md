# M8 动作、关卡、角色与武器升级

M8 承接已验收的 Win64 Shipping `M7_07/Attempt01`。以现有完整试炼为底，替换玩家和敌人的模板表现，改造正式路线并让刀刃轨迹与真实命中判定一致。阶段完成后由 M9 负责作品交付与面试准备。[M7-07 验收](Reports/M7_07_Verification.md) · [项目阶段计划](../Introduction.md#112-阶段计划)

暂定美术方向为受火侵蚀的石砌遗迹，借用现有暖铜、暗石、祭坛刻纹作为造型线索。入口、混合遭遇和守关者庭院用不同高度、轮廓和光线区分。玩家、三类敌人和武器采用同一组材质语言。先用游戏镜头做样板，用实际比例和效果校准批量制作的工时。

## 分批顺序

| 批次 | 交付 | 进入下一批的条件 |
| --- | --- | --- |
| **M8-01 动作模块** | 玩家走、跑、冲刺与战斗的正式动画，近战敌人、远程守卫、守关者的独立动作组 | 在开发图和正式试炼中实机验证动作、移速、事件时序与取消 |
| **M8-02 关卡地形与空间** | 正式三场试炼的不规则地形、路标、掩体、战斗空间、碰撞和导航 | 整条路线可通关，A/B 存档能继续和重试，敌人可达、镜头可用 |
| **M8-03 人物模型** | 玩家和三类正式敌人的特色模型、绑定、材质和动作重定向 | 四种角色在实机中可凭轮廓辨认，动作和挂点全部复验 |
| **M8-04 武器模型、动作与命中** | 与玩家匹配的短刃，握持、随身动作、刃段扫掠、反馈与调试 | 模型、动画与判定通过。**验收通过后提醒用户即将进入 M8-05 收尾** |
| **M8-05 整体细节与发布复验** | 动作、关卡、角色、武器联合细修，更新 Shipping 并实机复验 | 四项成果在同一候选包中通过，保存阶段报告与对比证据 |

M8-01 先验证一套骨架与一个武器代理模型。可以在该批同步预检 M8-03 的候选骨架，以减少整套动作做好后重绑的成本。M8-02 在副本中迭代。M8-03、M8-04 分别用最终模型和最终刀刃回验 M8-01 动作。每批独立留可回退的版本，小样通过后推广到同类资产。

## M8-01 动作模块

已进入 M8-01A。先接通项目自己的玩家 AnimBP，在开发图验证原地步态、空中状态、Montage 和 Blender 出片流程。A 完成后按玩家完整移动、玩家战斗、敌人动作与联合验收推进。全部通过后进入 M8-02。[M8-01A 操作指南](M8_01A_PlayerLocomotion.md)

### 动作交付

| 对象 | 交付动作与差异 |
| --- | --- |
| 玩家移动 | 自有 AnimBP 覆盖待机、起步、走路、跑步、急停、转向、冲刺起步／循环／收步、跳跃与落地。自由移动与锁定分别检验，锁定包含前后左右移动及后撤。保留方向闪避并补齐位移和动作的过渡。 |
| 玩家战斗 | 三段轻击采用明显不同的挥击方向、重心和节奏。检查挥击、治疗、破势、受击、硬直、死亡与恢复。用斜侧或侧视慢放核对前摇、有效帧、收招和接续窗口。 |
| 近战敌人 | 待机、发现、追击、急停、转向，两种可区分的近战出招，以及受击、硬直和死亡。攻击样式先定短促出招与延迟重击，按距离和冷却验证选择。 |
| 远程守卫 | 制作站定瞄射与退让后回身射击两套表现，区分起手、重心和收招。补齐拉距移动、受击、硬直和死亡。实际射击仍遵守停步、瞄准和视线条件，发射点随手部或装备移动，同一施放只生成一发。 |
| 守关者 | 保留现有横扫、突进与圆形冲击玩法，分别制作可辨的起手、命中段与收招，补齐两阶段衔接、移动、受击和死亡。三招复查范围提示与实际结算。 |

1. 用 Blender 或 Control Rig 制作姿势和节奏，也可采用许可允许的动作源作为起点。用 UE 的状态机与 Blend Space 管理移动，用 Montage 管理攻击和能力时序。冻结一套骨骼参考姿势、角色比例、手部武器挂点以及左右脚链后再批量制作。[UE 5.5 双足重定向](https://dev.epicgames.com/documentation/en-us/unreal-engine/retargeting-bipeds-with-ik-rig-in-unreal-engine?application_version=5.5)
2. 正式玩家冲刺以独立移动状态规划，M8-01 先核对输入映射和允许状态。持续冲刺与现有方向闪避单独验收。走／跑／冲刺速度、起步和制动由实际 CharacterMovement 驱动。先验证原地动画与移动速度的匹配，能力内有位移时只保留一方驱动位移。
3. 通过原生能力保留有效命中、连段输入缓冲和中断清理。重设 Montage 中的攻击、连段、技能生效和发射窗口，并对齐动作接触帧。敌人每种新招都验证提前打断、完整收招与重复出招间隔。[UE 5.5 Animation Notifies](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-notifies-in-unreal-engine?application_version=5.5)

**验收**　走跑冲刺起停自然、脚接地稳定，四类角色有清楚的速度和姿态差异。暂停、锁定、受击、死亡与 Retry 后状态恢复正确。玩家三段、敌人预警、出招与收招可从游戏镜头分辨，事件窗口、资源消耗及原有伤害流程回归通过。

## M8-02 关卡地形与空间

- 以 `L_ET_TrialRoute` 为脚本、遭遇与存档基线。用开发副本处理视觉和碰撞，验收后回接正式路线。保留正式地图包名、A/B 检查点 ID、遭遇与奖励 ID。需要移动节点时，验证原包存档在新地面能恢复并到达正确门区。
- 入口改为破损石阶、断墙与自然岩坡，以光线和连续路标引导到第一场；祭坛保留安全空间；混合遭遇用不规则掩体、高低差和侧路提供视线变化；守关者区用台地与宽战斗面，让横扫、冲刺和圆形冲击都保留可回避空间。
- 用 Blender 或 UE Modeling 制作不规则断墙、岩块、拱门和梯段，优先复用现有石材与光照。需要连续地面起伏时使用 Landscape Sculpt，按区检查坡度、脚部接触、碰撞台阶、镜头遮挡和敌人 NavMesh。对视觉小件用适当的简单碰撞或关闭导航影响，验证真正影响路径的障碍。[UE 5.5 Landscape Sculpt](https://dev.epicgames.com/documentation/en-us/unreal-engine/landscape-sculpt-mode-in-unreal-engine?application_version=5.5) · [UE 5.5 导航系统](https://dev.epicgames.com/documentation/en-us/unreal-engine/navigation-system-in-unreal-engine?application_version=5.5)

**验收**　沿入口、祭坛、混合遭遇、守关者到出口实际走通。保存前后同机位图，检查三处空间可辨、视线清楚、地形起伏自然。验证坡道与台阶不阻断，拳、刀刃和投射物符合掩体遮挡，玩家镜头及近战、远程和守关者均可正常战斗。A/B 重试和跨进程继续、清场开门、出口胜利通过。

## M8-03 人物模型

| 角色 | 首选造型方向 |
| --- | --- |
| 玩家 | 灰布与暗铜护甲的轻装试炼者。肩侧、短披布或腰部配件形成轮廓，右手握持区留出短刃和手指空间。 |
| 近战敌人 | 宽肩、厚重前臂与破损近战护具。加厚外轮廓，前摇姿态能从正面与斜侧读出。 |
| 远程守卫 | 瘦长、布帽或护颈，加入可辨认的远程装备和发射挂点。体态与近战分开。 |
| 守关者 | 高大重甲、残缺头盔与可辨认的二阶段发光区域。盔甲厚度和手臂活动范围按现有三招校准。 |

1. 优先用 Blender 制作角色服装、护甲、面部遮挡与特色配件，尽量沿用兼容的双足骨架。Fab 免费候选在实施时逐项对照骨架、拓扑、材质槽、LOD、可重定向性、允许采用的格式与许可证。先选一名玩家和一名敌人做快速装配，骨骼、轮廓、造型或授权不合适就切换到 Blender 路线。
2. 为不同骨架构建 IK Rig、设定参考姿势、为手脚与躯干映射链并离线导出。逐个检查胶囊、物理资产、Mesh 偏移、枪口、握柄挂点、Foot IK、远距 LOD，以及站直、奔跑、闪避、受击和死亡时的穿插。锁定镜头下仍能读到关节动作与对手轮廓。
3. 导入前登记作者、来源、许可、获得时间和版本。Fab Standard License 的规则区分嵌入项目的分发、协作者共享与独立资产再分发。公开源码仓只收录允许公开分发的原始资产，受限素材在本地或符合许可的协作库管理。给公开工程准备可构建的对应替代，并在 Shipping 分发前复核实际采用资产的条款。[Fab 许可](https://www.fab.com/eula) · [项目资产清单](AssetManifest.csv)

**验收**　正式图里的玩家、近战敌人、远程守卫、守关者均换成具有不同剪影的模型。在中远距离和锁定镜头下仍可分辨，非战斗到死亡的动作全部正确，挂点、落地高度、导航和碰撞范围可解释。提交源件或合规引用、模型与材料清单及操作截图。

## M8-04 武器模型、动作与命中

现有短刃来自 M7-01。模型刚性挂在右手，轻击真实伤害使用动画窗口内的手部轨迹扫掠。M8-04 将攻击来源移到刀刃，让刀尖、刀身和角色动作与判定同步。[M7-01 验收](Reports/M7_01_Verification.md) · [现有 Trace 组件](../EmberTrial/Source/EmberTrial/Private/Combat/ETCombatTraceComponent.cpp)

1. **模型。** 依据 M8-03 玩家手掌比例和护甲造型在 Blender 重做灰烬短刃，明确握柄、护手、刀刃、刀尖的剪影与比例，统一暗钢、做旧铜与绑带材质。校正握持原点与方向，并设置握柄、刀根和刀尖挂点。制作可用的低模、材质、必要的 LOD 与来源记录。
2. **动作。** 用最终模型为每段挥击制作实际可读的刀刃轨迹。分别调起手刀面角度、挥动、接触帧和收刀，检验从正面、侧面和锁定镜头都能看清刀刃。用手腕与武器挂点联动刚性短刃，换握或收纳时再配武器局部变换关键帧，并同步手指握持。验证待机、走跑、冲刺、闪避、受击和死亡时的握持。需要刀光时让特效取相同刀刃挂点。
3. **判定。** 复用 `UETCombatTraceComponent`、动画有效窗口和现有伤害链路。按前后帧采样刀根至刀尖，可加中间采样填补轨迹空隙。调试可视化叠加实体刃段、扫描范围、实际命中点和持续窗口。复用目标去重与墙体遮挡，确认阵营、无敌及同一次窗口最大一次扣血。切段、中断、死亡或失去武器挂点时立即收尾，避免旧采样点继续判定。M7 命中音效沿用实际扣血后触发。
4. **测试。** 分别检查近距离刀根、边缘刀尖、略超范围、快速挥动、较低帧率、背向与障碍遮挡，确认画面接触与结果一致。复查玩家按键、连段衔接与遗物真实伤害。

**收尾提醒**　M8-04 实机验收通过后，明确告知用户四项主体内容均已完成、接下来是 M8-05 整体细节优化。

## M8-05 整体细节与交付门槛

- 在正式试炼一起复看脚滑、闪避落点、镜头穿墙、披布与护甲穿插、攻击可读性、刀刃轨迹和音效同步。逐项按实际问题细修，不通过压小命中范围或绕过原有前摇来掩盖动画误差。
- 对比整体画面，包括材质色调、光照、路标、关卡节奏和战斗 HUD。用同一设备、窗口与画质分别采集 M7_07 和新候选的帧时间，单独记录高负载遭遇和切图。先量测，再决定网格 LOD、材质、光源或动画更新成本的调整。[既有测量基线](Reports/M6_06_Verification.md)
- 验证旧档兼容与完整流程。跑现有全量自动化及本阶段的针对性检查，构建新的 Win64 Shipping 包。检查启动菜单、设置、整条正式路线、A/B 读档、失败重试、胜利后重开，以及模型、Montage、武器和声音在 Cook 后仍可用。
- 归档同机位前后对照、关键命中回放、性能数据、实际工时和资产授权。M9 用该版本完成录屏、技术报告、简历、整体复盘、模拟面试和现场改动训练。
