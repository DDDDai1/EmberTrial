## 1. 本章结束时能玩到什么

正式测试地图里保留一个训练目标，并加入一个近战敌人。敌人感知到存活玩家后追击，在合适的距离停止、转向并发动一段有前摇的攻击；窗口内沿真实拳轨迹判定，合法命中使玩家扣血、受击并更新现有HUD。玩家可以移动、闪避、攻击敌人；敌人有自己的生命、受击与死亡状态。任一身体死亡优先取消自己的当前动作；玩家死亡后，敌人停止追击与攻击，不对尸体继续结算。

先使用Quinn和已有原地占位动画，单段攻击、单个敌人、固定测试房间。死亡继续冻结占位。M1-06再接失败重试 / 检查点；远程敌人、守关者、遭遇奖励及Blender关键模型属于后续范围。本章的可玩战斗不等于最终投递作品完成。

## 2. 技术选择与先要处理的兼容点

沿用[Introduction的AI路线](../Introduction.md)：**AIController + AI Perception + Blackboard / Behavior Tree + CharacterMovement / NavMesh**，不同时引入StateTree。C++负责有效目标、生命周期、任务边界与能力请求；行为树资产组织决策，Blueprint装配身体 / 资源 / 参数。

C1已解决共享战斗接入AI所需的两个条件，以下记录实际实现边界：

1. 轻攻击使用ServerOnly并限定Standalone / Authority，CanActivate分别检查本地玩家Controller与正确控制Enemy身体的AIController；保留暂停、生命、速度与动作门控。玩家25 / 敌人10共享原生实现。
2. 玩家胶囊Visibility=Overlap、Mesh NoCollision已由用户装配确认，真实敌人命中使玩家扣10并触发受击 / HUD；身体阵营关系在伤害前过滤。同方测试有Candidate后CombatTeam拒绝。

AI只发出行动意图；技能是否接受、命中谁、伤害多少、结束 / 取消由现有战斗层决定。Behavior Tree Task不能用固定Delay代替Montage结束，也不能直接调用SetHealth或进度条。攻击任务中止须取消自己启动的动作并清理订阅，不能留下旧任务完成回调。

## 4. 对象与代码职责

| 对象 | 职责与约束 |
| --- | --- |
| `AEmberTrialCharacter` | 共享身体 / 现有战斗命令；每个实例独立ASC、属性、生命状态；不复制一套EnemyHealth / EnemyDeath实现 |
| `BP_ETMeleeEnemy` | 直接继承原生共享Character；模型、胶囊、移动、AI Controller Class、能力Class等装配；不继承带M0输入 / 菜单业务的玩家BP |
| `AETAIController` | 管理当前受控身体、感知与目标生命周期；Ready撤销 / 失去控制 / EndPlay清理；后续运行 / 停止BT |
| Blackboard | 保存当前有效目标与必要决策数据，不作为生命 / 正在攻击的第二个真实状态源 |
| Behavior Tree / Task / Service | 高层选择、Move To、停步 / 攻击任务；仅必要任务活动期间更新，普通决策按间隔运行 |
| `UETGA_LightAttack` / Trace / Notify | 共用真实攻击执行与窗口 / 去重 / 遮挡；玩家与敌人可有不同GA Blueprint参数，能力实例与攻击序号各自独立 |
| CombatLife / HitReact / AttributeSet | 沿用单身体生命与反应；AI依赖生命状态，不能用Ready=false冒充死亡 |
| Presenter / HUD | 继续只观察玩家当前身体，敌人受伤不改变玩家血条；本章不另做头顶血条 |

AI留在`EmberTrial`核心模块，Public/AI与Private/AI。公开AIController头文件继承AAIController，所以A添加**Public AIModule依赖**；真正使用导航查询API时再添加需要的NavigationSystem依赖。核心不依赖UI、UMG或Editor模块；不另建空的Enemy专用模块 / 空C++身体子类。

生命周期上，感知、BB目标、任务订阅和本身体Ready / 死亡订阅分开拥有。换目标先撤销旧目标事件 / 路径，换身体先解绑旧身体。Ready表示属性链可用，不表示存活；EndPlay不允许因旧事件重新Run Behavior Tree。具体句柄与配置在对应批次提供，不在A预先搭一套测试状态机。

## 5. 资源、表现与性能

- **新增资源预算0元**：使用本地Epic模板Quinn、ABP_Quinn、已有攻击 / 受击Montage与真实Damage GE。敌人先靠独立摆放和朝向识别；材质 / 武器 / 最终角色稍后确定。
- **不Duplicate已有Character蓝图**：本机UE5.5.4已遇到原生AttributeSet子对象引用失效，敌人从原生EmberTrialCharacter创建，再逐项配置。
- **决策不放角色Event Tick**：感知事件与有限频率BT服务；日志记录目标 / 状态转移，不能每帧打印距离。Move To不每帧重新发起，失败要有等待 / 退路。
- **技能忙碌与寻路分开**：受击 / 攻击时按动作规则停走；不能依赖玩家Input Ignore来阻断AI路径跟随。D必须验证中断后的行为，不仅看到一次动画播放。
- **NavMesh先静态房间**：地面 / 墙是固定场景，身体不作为动态导航烘焙障碍；这不取消身体物理碰撞。复杂动态障碍 / Crowd不在单敌人批次提前引入。
- **真正测量留阶段专项**：绿色导航覆盖不是寻路成功，单敌人无卡顿也不是性能结论。M1-07再做固定场景Trace / 阶段包；后续3–6 / 最多8敌人的压力范围另测。

## 6. 按方案B验收，不重复设计旧测试图

每批用地图里这个正式敌人检查新增行为；需要受伤时复用正式左键攻击，需要玩家伤害 / 动作中断时复用已有3 / 4入口。不在PlayerController反复增加 / 删除五函数，不重做HUD重建、独立身体换控、MaxHealth全矩阵、闪避三帧率或M0打包。

A只查AI控制权、独立初始化、敌人被击 / 受击 / 死亡、地图导航覆盖、两次出生和清理。B才证明感知 / 路径跟随；C才证明敌人真实命中玩家；D把实际交战和两种死亡中止串起来。修改共享攻击后必须针对玩家攻击、取消 / 暂停做窄回归，不能用M1-04旧结果替代受影响部分。

困难的亚秒窗口不要求凭手感反复盲试。若对应批次需要这种边界，优先可观察状态 / 现有慢速手段；需要助手实际控制时按当次明确授权执行。上一章的窄测试授权不自动变成以后所有C++ / UI接管。
