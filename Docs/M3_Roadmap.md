## 2. 静态数据、逻辑状态与身体效果分开

| 所有者（后续实现计划） | 内容 | 寿命 |
| --- | --- | --- |
| UETRelicDefinition | 稳定ID、文本、图标软引用、槽位资格、加法参数 | 静态资源，不记录拥有 / 当前数值 |
| GameInstance层遗物库存域 | 拥有ID集合、已提交的两槽ID；不存ASC / Widget或GE句柄 | 当前进程，跨OpenLevel；NewRun确认后重置 |
| Character装备组件 | 对当前ASC应用后的句柄、装备就绪 / 提交协议 | 当前身体，结束精确移除自己效果 |
| LocalPlayer UI Presenter / View | 列表、临时选择 / 预览、焦点；发意图、显示业务结果 | 当前页面 / 本地玩家，不提交伪造成功 |

Controller会随切图销毁，不能单靠Controller字段保存Continue装备。原RunSession仍只负责地图 / 检查点 / 切图；后续独立库存域与其确认点协作，不把所有东西都塞进RunSession。以上生命周期合同尚未落地，01未新增组件或修改Character Ready；02A也只下发纯计算，无状态持有者。

## 3. 本阶段装备与资源语义

- 初始开发库存提供两件定义、两槽空；不是已完成掉落 / 拾取。最多两件，同一RelicId不能同时占两槽；拥有不等于装备，选择 / 预览也不改变装备。
- 后续只有安全祭坛内允许换装。正式安全入口未做前，M3-02用受限开发入口验证真实事务，不直接让Widget改ASC。
- 存活换装保留当前生命，最大值上升不免费治疗；下降只夹到新上限。预览不往玩家身上Apply / Remove GE。
- Retry / Continue重建身体：保留本进程已提交拥有 / 装备ID，先初始化基础、重建合法装备，再按最终上限恢复新身体生命 / 体力；治疗次数回默认、技能冷却清空。NewRun确认后回初始拥有 / 空槽；退出进程清空。M5再改为正式检查点快照恢复，菜单届时明确提示。
- 计划请求失败保留旧逻辑 / 身体结果；不能只回滚两槽ID而让Health已被临时上限下降裁掉。M3-02需要把属性变化、GAS同步回调及UI提交边界一起设计，不声称GAS天然具有数据库原子事务。
- 新身体基础GameplayReady沿用现义；新增EquipmentReady与开放输入 / UI的顺序在02落实，不悄悄把旧Ready改成“所有未来系统都就绪”。
