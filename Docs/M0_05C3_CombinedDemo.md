# M0-05C3：四动作组合演示与动画方案收尾

日期：2026-10-01；UE 5.5.4。预计手动 **15–25 分钟**，包含预演、录制和一次回看。

**C1、C2 已验收完成。**本批使用现有功能，检查它们在同一次游玩中的衔接，并留下约 **30–45 秒**的连续视频。无需新增 C++、蓝图节点、美术资源或自动测试；没有修改源码时不用为了录像再 Build。

## 1. 这段视频要证明什么

画面中连续出现：**移动 / 转向 → 攻击 → 闪避位移 → 受击打断 → 暂停 / 恢复 → 交互提示与激活 → 恢复移动**。

它是 M0 技术与占位素材试验，不是最终投递宣传片。当前上排 1 / 2 / 3 是调试输入；3 手动模拟受击，尚未连接敌人、伤害、体力或无敌帧系统。不要为录像增加假敌人、假扣血或特效。

| 已验证的基线 | 本批只看画面与组合效果 |
|---|---|
| SKM_Quinn_Simple / SK_Mannequin，ABP_Quinn 继承 ABP_Manny | 是否明显缩放、扭曲、抽动或衔接断裂 |
| 攻击约 1.033 s、闪避姿势 0.700 s、受击约 0.633 s | 每段姿势能否辨认，能否自然返回待机 |
| AS 为原地动画，程序化 Root Motion Source 负责闪避 | 胶囊带角色移动，没有 Mesh 单独漂走或位移结束后继续滑行 |
| 自身右侧 150 cm / 0.30 s，Montage 完成后解锁 | 位移与身体倾斜方向是否一致，停下后是否仍保持剩余动作 |
| 受击优先级高于攻击 / 闪避 | 中断及时，受击后能恢复操作 |
| E 交互与 P 暂停已有实机验收 | 同一轮操作中提示、焦点和输入恢复是否仍正常 |

轻度占位动作生硬可记为后续美术改进；不能忽略明显穿模、姿势跳变、卡状态或持续漂移。墙壁 / 坡面及完整输入边界不重做，先前验收继续保留。

## 2. 开始前，约 2 分钟

1. 回到 **`/Game/ThirdPerson/Maps/ThirdPersonMap`**，使用原来的玩家和 GameMode；保存已有改动。
2. 停止旧 PIE，重新 Play，让 A / B 的一次性激活状态重置。
3. 点击游戏视口，使它获得焦点。在 A / B 附近找一块角色右侧至少 3 米空地；通过走路就位，不移动 PlayerStart 或修改测试物体。
4. 预演一次下面的按键顺序，确认录制范围能同时看清角色全身、脚下地面和 UMG。
5. 保持当前正常画质和窗口设置即可；关闭挡住画面的控制台 / Output Log。不要用慢放、时间膨胀或修改 Montage 速率来展示动作。

录制分辨率能清楚辨认动作和文字即可，优先现有 1080p；视频 30 或 60 fps 均可。视频编码帧率与游戏实际 FPS 分开记录，不把录像当性能测试。

## 3. 连续演示路线

下表时间是安排参考，不是需要严格卡秒的测试。走到交互物体花得更久可以自然延长，不要剪掉中断和恢复过程。

| 参考时段 | 你操作什么 | 看见什么算正常 |
|---|---|---|
| 0–4 秒 | WASD 移动、转动一次角色，松开按键站定 | 角色停止，没有残留移动 |
| 4–7 秒 | 站定按一次 **1**，等待攻击完整结束 | 攻击姿势完整，自动回到待机 |
| 7–10 秒 | 按一次 **2**，等待动作结束 | 向角色自身右侧移动，先停位移，后结束姿势 |
| 10–14 秒 | 再按 **2**，紧接着约 0.1 秒后按 **3** | 已开始的闪避在走满前停住，切入受击，随后回到待机 |
| 14–23 秒 | 站定按 **1**，立即轻按并松开 **P**；菜单停留约 2 秒，鼠标点击“继续”，等原动作结束 | 菜单打开，角色动作冻结；继续后动作接着完成，视口恢复输入 |
| 23–35 秒 | 走近 A 或 B，提示出现后按一次 **E**；稍等，再走出范围 | 激活提示立即更新，离开后隐藏 |
| 35–40 秒 | 在范围外移动几步、跳一次、落地后松键站定 | 移动 / 跳跃 / 落地正常，无卡键或持续漂移 |

重要操作细节：

- 1 仍要求基本静止。松开移动键、确认角色停下后再按，拒绝移动攻击不是故障。
- 2→3 不要同时按。如果第一次没赶上位移窗口，只重试这一段预演；正式录像可重新开始一遍。
- P 是**松开时切换**。选择较长的攻击动画展示暂停，更容易看清，不需要再次挑战 0.30 秒闪避内的暂停时机。
- 预演如果已激活目标，正式录制前停止并重新 Play 即可恢复；不用改蓝图变量。
- 录制中有异常就保留这段，告诉我大致秒数；不用反复录到“看不出问题”。

## 4. 怎么录和保存

使用你已有的录屏工具即可。如果没有常用工具，可先试 Windows 的 Xbox Game Bar：

1. 焦点放在正在运行的游戏 / UE 窗口，用 **Win+Alt+R** 开始录制；也可 **Win+G** 打开捕获控件。
2. 隐藏录屏控件后回到游戏窗口，按第 3 节完成一遍。
3. 再按 **Win+Alt+R** 停止。通常在 Windows“视频 / Videos”下的“捕获 / Captures”找到 MP4；以捕获界面显示的实际位置为准。

快捷键和默认保存位置见 [微软 Game Bar 录制说明](https://support.microsoft.com/en-us/accessibility/windows/use-a-screen-reader-to-record-your-screen-with-xbox-game-bar)。本机是否启用 Game Bar 尚未检查；如果快捷键无反应或录像黑屏，反馈现象即可，不必因此改游戏代码或安装新工具。

先录 **3 秒试片并回看**，确认拍到游戏画面和 UI，再录正式片段。无需配音、剪辑、配乐、字幕或开场动画。

将正式视频复制到已准备的目录，例如：

```text
E:\UE_Project\Demo\Artifacts\M0_05C3\M0_05C3_Combined_01.mp4
```

也可保留在录屏工具原目录，只需反馈准确路径。此目录被 Git 忽略，大视频不会进入普通提交；路径记录不能代替异地备份。本轮只保存到本机，不上传或发布。

本批通过后形成 M0-05 动画路线结论：模板共享骨架 + Control Rig 占位 + 原地 AS / Montage + CharacterMovement 程序化位移在本 Demo 可继续采用。最终战斗资源、武器挂点、命中窗口、受击来源和正式输入设计继续后续阶段；本次不将调试组件当作最终战斗框架。
