## 2. A与后续检查边界

首次验证新Runtime UI / 地图在Cook后齐全，所以重新打包当前工程有必要；之后配置与资源不变时沿用同一包做性能采样。游戏源文件 / Cook资产变动才重新出Attempt02等新版，不能用旧包验证新Source。

按方案B，A检查打包后的新增边界与一条可玩流程：菜单默认地图、Cook地图、中文 / 动画 / 正式左键、暂停焦点、检查点Retry / Continue、新进程清除会话。AI / 属性 / 换身体 / 命中FPS全矩阵沿用旧验收；只有失败才打开对应窄排查。

性能基线先测量后解释。A的1280×720窗口只是功能运行条件；B再固定1920×1080及明确画质 / 帧率配置，记录本机RTX4060 Laptop / 约16GB内存和预热条件。Development日志 / Trace会增加开销，单敌人灰盒结果不能承诺最终美术场景60FPS；M2深化和美术接入后按变化重新量测。

## 3. 阶段收口标准

1. 当前Win64包真正脱离Editor运行并有独立日志；包内菜单 / 战斗 / 检查点闭环通过。
2. 至少一份真实Insights Trace和可复述结论，说明采集条件、瓶颈证据与限制，不能只有平均FPS截图。
3. 有可复用的有限校验入口；正常配置通过，隔离负例报告准确路径 / 规则，工具无运行时模块污染。
4. M1报告 / Bug记录 / 来源清单更新，以实际用户工时校准M2；不把这版灰盒包当最终招聘作品。
