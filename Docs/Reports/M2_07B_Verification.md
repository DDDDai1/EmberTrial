## 4. 主循环与GPU场景范围

只计完整落在窗口内、起止有限的事件；56,037条主循环导出中最后一条未闭合，排除。相邻Tick开始之差作为主循环间隔；P50 / P95 / P99用最近秩法`ceil(q×N)`，单位ms。

| 窗口 / 指标 | 样本数 | 均值 | P50 | P95 | P99 | 最大 | >50ms |

| Idle225–245：主循环开始间隔 | 3636 | 5.498 | 5.462 | 5.915 | 6.760 | 12.805 | 0 |
| Combat268–279：主循环开始间隔 | 2073 | 5.304 | 5.288 | 5.714 | 5.944 | 10.714 | 0 |

| Combat268–279：GPU场景包裹范围 | 2073 | 4.668 | 4.670 | 4.813 | 4.868 | 5.011 | 0 |

Tick自身持续时间均值另为5.498 / 5.304ms，包含下层及等待；不是排除等待后的玩法运算成本。以上主循环间隔不是显示器呈现FPS，CPU / Render / GPU彼此重叠，不能相加换算帧率。

GPU统计采用GPU1上Depth0的`Unaccounted -  Frame: …`包裹范围，结合本机DeferredShadingRenderer中的作用域确认其为场景渲染范围；**不是完整GPU Frame、全部队列忙碌时间或呈现延迟**。“Unaccounted”这个名字也不表示整个范围都是未归因独占成本。本轮导出的GPU事件实际在GPU1，GPU2无记录，不把空队列写成GPU耗时0ms。

持续内部窗口没有超过16.7ms的主循环间隔，但不据此认证最终三轮路线或完整美术负载。交战较待机略低也不是代码优化收益：包没改，镜头 / 可见场景、渲染工作量和环境会变化。
