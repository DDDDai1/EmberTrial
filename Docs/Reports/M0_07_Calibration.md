# M0-07：工期、资源与风险校准

日期：2026-10-01。**M0-07 完成，M0 整体退出条件已满足，进入 M1。**本报告基于此前验收、首次打包证据和用户本轮确认；最终游戏、正式性能和投递材料仍待开发。

## 1. 已确认约束

| 项目 | 确认结果 / 执行方式 |
|---|---|
| 有效投入 | 用户确认每周约 30 小时，包含实现、理解、验证与记录 |
| 投递日期 | 暂无硬期限；保留 P0 可玩版本提前展示 / 投递的安排，不等待所有可选功能 |
| 资源预算 | 总额约人民币 100 元，以零成本资源为基础；不是已授权购买或已发生支出 |
| 输入范围 | 用户有手柄，明确不开发手柄功能；交付与测试采用键盘 / 鼠标 |
| 引擎与 IDE | UE 5.5.4；CLion 2025.3.3；保留 MSVC 14.38 / SDK 10.0.22621.0，UAT / UBT 构建 |
| 协作方式 | 全部 C++ 默认文档给代码、用户手动实现；直接读取和审查可主动进行，改源码需用户明确要求 |
| Blender | 中后期试做主武器 / 祭坛等重要模型；先有尺寸与挂点规格，不增加角色重绑作为 M1 前置 |

手柄支持是原计划额外安排，截图 JD 没有单列这项要求。手柄专用映射、按键图标切换、震动及断连开发 / 测试不列入交付范围；继续落实鼠标 / 键盘焦点、Confirm / Back、暂停恢复和输入门控。不能把尚未做的手柄支持写入简历或演示说明。

## 4. 工时口径与排期

M0 已报告手动投入 **673 分钟 / 11 小时 13 分钟**；本次等待 **26 分钟**另记。二者合计是已报告的 **11 小时 39 分钟**，不是完整 M0 总劳动时间：未计时的排障、助手实施 / 审查及早期构建等待仍未统计。

原 M0 预算 20 小时可留作规划参考，不能据局部已报时间认定全阶段只用了 11 小时或按比例缩短后续阶段。

保留 Introduction 的原阶段预算：M1–M8 基础合计 **390 小时**，另保留全项目的 **100–140 小时缓冲**作为保守剩余预算，即 **490–530 小时**。在每周 30 小时下，约需 **17–18 个有效投入周**；这是排期推算，不是承诺或投递截止日。移除手柄暂不直接扣减预算，余量用于战斗、动画 / 美术与 UI 集成，M1 完成后用正式纵向功能实耗重新估量。

M1 先按基础 **40 小时**推进；周分配暂按功能 / 表现 18 h、验证 / 性能 5 h、源码 / C++ 理解 4 h、记录 / 复盘 3 h。构建等待可用于读取代码和写记录，但时间账不重复累计。已有动画和首次打包减少了未知风险，尚不能证明 GAS、AI、重试 / 存档或完整 UI 的开发速度。

早期 P0 展示沿用原约 180–240 小时累计规划口径；30 小时 / 周约 6–8 个有效周，仍须先通过实际 P0 门槛。无需现在等待或查询岗位开放情况，准备投递时再核实。

## 5. 剩余风险与决策

| 风险 | 现有判断 | 行动 / 重估触发点 |
|---|---|---|
| 原型状态与正式战斗重复 | M0 PracticeAction 是已验证的练习组件 | 正式玩家由 GAS 持有战斗状态；同一 Pawn 不同时启用两套动作状态机 |
| GAS / AI 实际熟悉度 | 用户有 Gameplay / UI 经验，尚无本项目正式链路证据 | M1 做单次攻击 → 敌人扣血 / 死亡；小试验约 12–16 h 仍阻塞则拆开排查、重估，不堆平行实现绕过 |
| 动画最终品质 | 零成本占位路线可行，最终武器 / 命中观感尚未做 | 控制动作数量，先保证可读性；预算不足时优先自制 / 调整，先试做再扩量 |
| 内存与 Cook 等待 | Build 时可用内存低、首次 Cook 较长 | 减少后台负载、采用必要构建；不要求购买硬件或无依据修改 UBT 并发 |
| UI 归属与 Pawn 更换 | M0 UMG 目前由练习角色管理 | M1 正式 Controller / LocalPlayer 装配 UI；订阅、重试和重新绑定列为验收条件 |
| 模块 / IDE 索引 | 当前 CLion 适配脚本只覆盖 EmberTrial 模块 | 新增 EmberTrialUI 时配套扩展索引上下文；真实构建仍以 UBT 为准 |
| 过程日志覆盖 | 第一轮包内运行日志未独立留存 | 多次运行使用不同绝对日志名，原始证据留在忽略目录，摘要进 Docs |
| 范围与期限 | 暂无硬期限，容易增加功能或延后投递 | 冻结键鼠单人动作 / UMG 范围；每周交付可玩增量，按 P0 / P1 门槛判断 |

## 6. M1 范围与交接

M1 退出条件：一间小房间内，从主菜单进入，攻击一个近战占位敌人、看到 HUD / 死亡或胜利反馈；失败可重试、继续检查点原型并退出；得到新的可独立运行包。不在这一阶段一次完成全部敌人、Boss、6 遗物与存档迁移。

| 顺序 | 小任务 | 设计边界 |
|---|---|---|
| M1-01 | 正式纵向测试地图 | Basic 房间、可靠出生、复用已验证输入 / 提示；保留 M0 证据 |
| M1-02 | 正式对象与模块边界 | EmberTrial 核心、EmberTrialUI 展示；Gameplay 不依赖 UMG，Editor 模块在校验器真正需要时引入 |
| M1-03 | GAS 基础属性与 HUD 数据流 | 最小 Health / MaxHealth 与 ASC；事件同步，UI 不维护第二份规则数据 |
| M1-04 | 单段攻击与受击 / 死亡 | 正式动作单一所有权、一次命中去重、取消清理；其余能力在 M2 深化 |
| M1-05 | 一个近战敌人 | 感知 / 追击 / 单次攻击 / 死亡，先完成可玩的遭遇 |
| M1-06 | 主菜单、失败重试 / 检查点原型 | Controller / LocalPlayer 装配和重绑，重试不残留旧订阅 |
| M1-07 | 最小校验 / 日志 / Trace 与阶段包 | 正常 / 失败闭环、包内资源、真实证据；记录实际工时后再校准 M2 |
